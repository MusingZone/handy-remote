Dictation feedback guide

When a dictation comes out wrong, report it in ten seconds. Analysis, tuning and verification then happen in the background without interrupting you.

One report, start to finish

  1. Reportyou
    Right after a wrong dictation, press the report hotkey you bound to voice_feedback.py report, or choose the report entry in the Handy Remote tray menu. The newest dictation is preselected: fix the wrong parts and press Ctrl+Enter. With "replace the just-typed text" checked, the text in the original window is replaced by your correction as long as the caret is still at its end (Ctrl+Z undoes it).
  2. Analysisbackground, about a minute
    A blue dot appears on the tray icon. The text of that dictation, the server's record of it (draft, raw and final text, timings) and your correction go to the configured analyzer (Copilot CLI or an OpenAI-compatible model; the recording stays on this PC), which classifies the problem and proposes only safe changes: add a hotword, add a replacement rule, adjust a streaming parameter. Problems that need code changes go to a backlog. Replacement rules are first tried against your dictation history so you can see how many past dictations they would touch.
  3. Your reviewyou, whenever convenient
    When the analysis is done the dot turns orange. There is no hurry: it stays until you look. Click the tray icon to open the suggestions; each one explains why, and confident ones are preselected. Choose "Apply selected", "Reject all" or "Later".
  4. Takes effectbackground, seconds
    Accepted changes are written to the server's lexicon (the previous version is backed up on the server and locally). The server reloads it, so the next dictation already uses it; nothing needs restarting.
  5. Automatic checkbackground
    The reported recording is transcribed again with the new lexicon and compared with your correction. Better or unchanged: no message at all. Only when it got worse, or the check failed, does the orange dot come back; click the icon to read the notice.

Tray icon

Icon Meaning Click
Plain icon Nothing waiting Opens Handy Remote
Blue dot A report is being analysed Opens Handy Remote (the dot changes by itself when done)
Orange dot Suggestions to review, or a notice Opens the review window / the notice

The tray menu also has entries to review suggestions, report the last dictation and open this guide.

What is worth reporting

  • Names, product names and technical terms that keep coming out wrong: the easiest to fix with hotwords or replacement rules.
  • A word that is consistently replaced by a homophone.
  • Clearly wrong punctuation: an extra comma, a missing sentence break. These tune the splitting parameters or go to the backlog.
  • Missing words, swallowed words, high latency: the server record is attached so the cause can be found.

A one-off error caused by mumbling is not worth a report. Keep one sentence per report and only fix the wrong parts of it; the analysis is more accurate that way.

Where the data lives

  • Reports: %LOCALAPPDATA%\handy-remote\feedback\reports\ (recording, your correction, the analysis and your decision), unless reports_dir says otherwise.
  • Local lexicon backups: ...\feedback\lexicon-history\; the server keeps its own history too.
  • Backlog of code-change ideas: ...\feedback\backlog.md.
  • Settings: %APPDATA%\handy-remote\feedback.toml (see feedback.example.toml).
