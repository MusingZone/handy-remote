# 云端语音识别与大模型润色

Handy Remote 的语音识别可以在三个地方进行：本机（上游 Handy 的模型）、[Handy Remote 服务器](SERVER-SETUP.md)，或者**公共云端语音识别 API**。不论识别在哪里进行，都可以在上屏前用**语言模型**对文本做一次润色和结构化。

English: [../CLOUD-AND-LLM.md](../CLOUD-AND-LLM.md)

## 云端语音识别

打开 **设置 → 云端识别**：

1. 打开 **使用云端识别**，选择服务商，填入 API 密钥。
2. 按 **测试**：会上传一秒的轻微测试音，并报告往返耗时。
3. 按 **保存**。

云端识别和远程识别互斥：打开其中一个，另一个会自动关闭。

| 服务商                      | 调用方式                                      | 默认模型                      |
| --------------------------- | --------------------------------------------- | ----------------------------- |
| OpenAI                      | `/audio/transcriptions`                       | `gpt-4o-mini-transcribe`      |
| Azure OpenAI                | 部署的 `/audio/transcriptions`（`api-key`）   | 你的部署                      |
| Azure AI Speech             | 快速转写 API（`<region>` 终结点）             | —                             |
| Google Cloud Speech-to-Text | 用 API key 调用 `speech:recognize`（≤ 55 秒） | `latest_long`                 |
| Deepgram                    | `/listen`                                     | `nova-3`                      |
| AssemblyAI                  | 先上传再轮询结果                              | `universal`                   |
| ElevenLabs Scribe           | `/speech-to-text`                             | `scribe_v1`                   |
| Groq                        | 兼容 OpenAI                                   | `whisper-large-v3-turbo`      |
| Mistral Voxtral             | 兼容 OpenAI                                   | `voxtral-mini-latest`         |
| 阿里通义 Qwen3-ASR（百炼）  | chat completions + `input_audio`              | `qwen3-asr-flash`             |
| 硅基流动 SiliconFlow        | 兼容 OpenAI                                   | `FunAudioLLM/SenseVoiceSmall` |
| 自定义                      | 任何兼容 OpenAI 的服务器（密钥可选）          | —                             |

- 接口地址和模型按服务商分别保存，留空则使用默认值。需要其他区域、代理或自建兼容服务时，可以修改地址。
- 当前选择的识别语言会传给支持指定语言的服务；选 "auto" 时由服务自动检测。
- 只支持整段识别：停止录音时整段上传一次，没有实时预览，也没有逐句上屏。
- **隐私**：
  - 录音会离开本机，按服务商的条款处理。
  - API 密钥只保存在本机的设置文件中。
  - 识别进程通过环境变量拿到密钥，不会出现在命令行或日志里。

## 大模型润色（规整与结构化）

在 **设置 → 高级** 中打开 **后处理**，侧栏会出现 **后处理** 页面。在上游 Handy 后处理的基础上，增加了以下功能。

**每次听写都润色**

- 打开后，每次听写在上屏前都经过所选模型和提示词处理，而不只是按后处理快捷键时。
- 开启期间不再逐句上屏：模型改写完成后一次性上屏。
- **单次跳过**：这次听写会润色时，浮窗取消按钮旁有一个闪烁的星标。点一下，这次就直接上屏识别结果（录音中再点一下可以恢复）；润色进行中点它，立即放弃润色、上屏原文。下一次听写照常润色。

**「Polish & structure」提示词**

- 首次启动时自动添加；如果原来没有选中任何提示词，就选中它。
- 它会：
  - 保持原语言和原意；
  - 修正标点和明显的识别错误；
  - 去掉口头禅和说错后的改口；
  - 把数字写成阿拉伯数字；
  - 把口述的结构变成排版：
    - 「第一点……第二点……」或 first… second… 变成编号列表，每项另起一行，以 `1.` 开头；
    - 说「换行」变成换行，说「新段落」变成空一行；
    - 说出来的标点名称变成符号。
- 可以像其他提示词一样修改。删除后不会再自动添加。

**更多服务商**

- 本机兼容 OpenAI 的服务：Ollama、LM Studio、llama.cpp server、Foundry Local、OpenVINO Model Server、Lemonade。地址可改，不需要密钥。
- 云服务：DeepSeek、阿里通义（DashScope）、Moonshot Kimi、智谱 GLM、硅基流动、Google Gemini、Mistral。
- 上游原有的 OpenAI、Anthropic、Groq、Cerebras、OpenRouter、Z.AI 等仍然可用。

**查找本机模型**

- 同时探测各服务的常用地址（以及 `foundry service status` 给出的地址），列出正在运行的服务及其模型。
- 推荐的是 3–9 B 的小型指令模型，优先 Qwen。嵌入、语音、视觉、代码和推理（thinking）类模型不会被推荐。
- 按 **使用** 即选中该服务和模型。

**速度测试**

- 用当前服务商、模型和提示词处理一段示例听写：先预热一次，再计时三次。
- 显示中位耗时和输出结果，便于判断这个模型是否又快又好，值得每次听写都等它。

**GitHub Copilot（Copilot bridge）**

- [Copilot bridge](../../../tools/copilot-bridge/README.md) 是一个只监听本机回环地址的小服务，把你 Copilot 订阅里的模型以兼容 OpenAI 的接口提供出来。
- **查找本机模型** 会列出它提供的模型。请按自己的订阅选择并测速，不预设某个账号专属的模型。
- 使用它时，听写文本会发送给 GitHub Copilot。

**我的规则**

- 写给模型的个人要求，每行一条，存在一个纯文本文件里：默认是应用数据目录下的 `refine-rules.txt`，也可以指定任意文件，例如放在同步文件夹里，让多台电脑共用。
- 每次听写都会加进所选提示词（放在 `${rules}` 处；提示词里没有这个占位符时，放在转写文本那一段之前），并且优先于提示词自带的规则。
- 以 `#` 开头的行是注释。每次听写都会重新读取文件，用任何编辑器修改都立即生效。
- **自定义词汇** 会自动作为一条规则加入：原样保留，不翻译、不改写。

**自定义（Custom）服务商**

- 每个自定义端点可单独选择认证方式：自动（OpenAI 用 Bearer、Anthropic 用 `x-api-key`）、Bearer、`api-key` 或无认证。不会同时发送多个认证头。

**私有端点配置**

- 把 [endpoints.example.json](../endpoints.example.json) 复制到仓库外的私有目录，填写自己的名称、地址、模型与认证方式。
- 在服务商下拉框旁点 **导入端点**，条目会进入本机设置；每个端点分别保存模型和密钥。
- ID 必须是唯一的 `custom_<name>`，改名称或地址时保留 ID。格式为版本 `1` 的 UTF-8 JSON，最多 128 KiB、100 个端点。
- `api_format` 支持 `openai`（默认）、`anthropic`；`auth` 支持 `auto`（默认）、`bearer`、`api_key`、`none`。
- 再次导入会更新同 ID 条目，不删除其他条目、不切换当前服务商、不覆盖密钥；省略 `model` 会保留已选模型。文件无效时不作任何更改。
- 端点已有密钥时，禁止通过导入改换 URL：先清空该端点的 API Key，再导入新地址并填写新服务的密钥，避免将旧密钥发送给新服务。
- 文件禁止放密钥，未知字段会被拒绝。密钥只在应用的 API Key 输入框填写，保存在未加密的本机设置中；不要把设置文件提交或同步到共享位置。
- 导入不会访问服务；本机发现只探测回环地址，不探测远端地址，也不携带密钥。
- 本机发现和 LLM 请求都不会跟随 HTTP 重定向，请直接配置最终的 API 基础地址。

本机服务和新增的云服务会关闭推理（thinking）：推理要多花几秒，对这个任务没有帮助。

### 怎么写规则

不同模型在细节写法上不一致（三楼还是 3楼、三个问题还是 3个问题、会不会调换语序），规则就是用来把这些定下来的。测试中有效的写法：

- 一条规则只管一件事，并附一个简短例子：`楼层用阿拉伯数字（三楼→3楼）`。
- 规则有例外时，把例外写进同一条，并给出错误写法：`数量和时长保留汉字：三个问题、五分钟，不要改成3个问题、5分钟`。拆成「时间用数字」「数量用汉字」两条时，模型把五分钟改成了 5分钟。
- 留几条测试用的听写和期望结果，改规则后重跑一遍，其中要有规则例子里**没有**出现过的句子。

建议：

- 先用自己的服务商和模型运行 **速度测试**，再试有代表性的听写。延迟与效果取决于模型、硬件、服务和个人规则，不把维护者机器上的结果作为默认值或保证。
- 这个任务很少值得用重型模型：慢好几倍、贵好几倍，效果却不比加规则更好。
- 模型出错或 60 秒内没有返回时，Handy 会直接上屏未润色的原文。
- 经常长段口述时，可以关掉「每次听写都润色」，只在需要改写时按后处理快捷键。
